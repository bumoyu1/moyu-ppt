# 需求、能力与状态

本文件是需求确认、standard/autonomous 节奏、能力快照与降级的唯一定义处。风格怎么问见 [style-discovery.md](style-discovery.md)，决定记录格式与门禁见 [workflow-gates.md](workflow-gates.md)。

## 需求最小集

有素材时先把素材读完，写出内容骨架：知识型还是演讲型、主线、每一节讲者要讲什么与原文依据（[内容骨架](content-structure-method.md)）。骨架通过 `content_map.py check` 后用 `deck_state.py artifact content_map content-map.md` 登记，再谈页数。然后把关键设计决定集中确认：素材与交付类型、受众/用途、画幅/页数、图文融合占比、整体风格意图，以及已有字体/品牌约束。没有品牌规范或字体偏好时不追问，具体搭配由设计师提出并展示。语言跟随来源；输出路径等非设计细节自行处理。品牌图像、字体图像与风格图像按用途分配。

初次有材料时，先给用户看内容骨架的要点：类型判断和理由、主线、各部分讲什么、有哪些待确认的推断。页数给两到三档，每档写清哪些节不上屏；用户已经给了页数而装不下时，说明要舍掉哪些节，请用户选加页还是确认舍弃。再简短列出已知信息，针对缺失项给一组建议（`deck_state.py brief --proposed` 记下），用户可修改或回复“按这组建议”（`decide intake --apply-proposal`）。档位定下后，把不上屏的节在骨架里标明理由。16:9、约8–12页这类值是依据内容提出的建议，用户选定前不执行，也不自动取区间上限。已给的值（如10页/21:9）直接写入 `brief` 并锁定；受众和用途可以合成一句让用户选。

图文融合占比是建议组的固定一项，建议值跟内容类型走：演讲型视觉主导 80/20，知识型 70/30 上下（如 `brief --visual-ratio 70/30 --proposed`）；用户要更高的视觉占比时靠加页容纳内容，不删知识点。展示时说明三点：它是全篇的设计预算，不是像素面积测量；大部分页按这个比例做，文字密的页（定义、比较、数据）最多低 5 点（如 85/15 最低 80/20），再放不下就拆页；用户可以选整体占比（如 80/20、60/40、50/50），也可以说按内容逐页定（`--visual-ratio per-page`）。用户要别的下限时用 `brief --visual-floor 78` 记下；改基准时，单独设的下限回到默认。写法为“视觉/文字”、两数之和为 100。`decide intake` 要求简报里有这一项；用户已经说过的占比直接写入，不再重问。状态里没有记录这一项时按 80/20 执行，`status` 会提示；补记的值不是 80/20 时，需求与样页确认自动失效。

标题排版也是建议组的固定一项，二选一（`brief --title-layout uniform|free`，也可以直接写中文名）：

- **统一版式**（uniform）：内容页标题每页同一位置、同一大小，靠字号锁、字号样板和出图后测量来保证。适合汇报、课件和字多的知识型，观众翻页时会直接对比标题。
- **自由构图**（free）：标题的位置、大小和排法跟着每页的画面走，全篇只锁配色、字形、材质和画法；标题字数不用写齐，不测字号。适合分享、演讲，以及插画、游戏这类画面感强的风格。

建议值跟内容类型和风格走：演讲型、图占七成以上、或用户点名了画面感强的风格，建议自由构图；其余建议统一版式。展示时说明：自由构图下标题只能做到字形一致、大小相近，要严格一样大就选统一版式。这一项要在写文案稿之前定，因为它决定同类页的标题字数要不要写齐。`decide intake` 要求简报里有这一项；之后改选，需求、文案与样页确认自动失效。详见[标题排版](visual-director-method.md#标题排版统一版式或自由构图)。

标准模式拿到关键决定后再确定全篇规划。等待期间继续读素材、提取页型、检查已有资产；依赖风格答案的新搜索等回复后再做。用户明确“没想法，先找方向”即可探索，无需再审批搜索词。

需求确认后先写文案稿：把全篇每页要上屏的每一行写成一份 `page-copy.md`，一次给用户看并取得确认（`decide copy`），再找灵感和做设计。写法见[内容骨架](content-structure-method.md)第 10 节。

用户点名收藏模板或说“用上次那套”时，按[模板库](template-library.md)先查本地名称、标签、预览并载入明确版本；只在候选有歧义时询问。记录 template_id/version 与当前覆盖项；收藏存在不代表覆盖新任务的要求。只查找/保存/载入模板的请求用 requested_output=template。

## standard 与 autonomous

默认 standard。用户明确说“页数和风格你来定，直接做”“全程不用问我”等，才按授权范围自主决策：`deck_state.py delegate --quote "用户原话" --scopes intake,copy,visual,pilot`，scopes 只写确有授权的部分。“帮我做PPT”、只给素材、选择一个风格、在某一轮回复“默认”，都只确认当时展示的内容。偏好可包括图文预算、参考权重、品牌规范与节奏。autonomous 也照常完成字体方案、代表页自检和文件验证。

## 偏好与能力分开

使用平台、生图方式和检索 key 由 `configure.py` 管理，保存在用户自己的配置目录，首次使用时按[首次配置](setup.md)引导一次；`configure.py status` 显示已配置就不再问。其中记录的平台与生图方式是用户的选择，换了环境或当前会话没有对应工具时，重新检查并如实说明，不沿用不存在的内置能力。偏好存用户配置目录或 deck，密钥只放环境变量或系统凭据。

执行前用 `deck_state.py capabilities key=value …` 记录能力快照：平台工具或 provider/model、生成/编辑能力、多图引用及上限、尺寸、运行时、PPTX 装配工具。内置工具不公开模型身份时记 platform-managed，不猜测型号。覆盖模型前核对实际提供方的支持；官方上线不等于第三方代理可用。

脚本需要 Python 3.9+ 与 Pillow；PPTX 装配另需 python-pptx。内置生图只免外部密钥，拆分/检查/导出仍需要运行时。平台若提供等价结构化工具可以替代，但须满足同样的检查，并如实说明脚本没有运行。

## 状态

`deck_state.py init` 创建 `deck-state.json`，含 requested_output、skill_runtime（实际路径、版本、读取时间）、source_files、assumptions、capabilities、workflow 与 template_offer。内容骨架登记在 workflow.artifacts.content_map；确认需求时会记下它当时的内容，之后骨架有改动，`status` 会提示重新给用户看。workflow 是执行门禁的唯一决定来源；状态里别的字段（如 pace 字符串或 completed 列表）不能代替它。真实用户选择用 `decide`，agent 自己的假设用 `assume`，两者分开；等待时间不算批准。

refs-review、visual-proposal、配置 source 等文字描述随 workflow 决定同步更新，同一份材料里不能同时出现“尚未答复”和“用户已选”。

搜索前另存 `inspiration-plan.json` 作为检索依据（字段见[检索方法](inspiration-search-method.md)）。它是 intake 的工作材料，不代替 workflow 中的需求/视觉/样页决定。已有充分参考可以不搜索；只读分析旧结果时不必补造历史回答。用户改变风格想法时先更新简报，受影响的查询与候选重新评估。

恢复时先运行 `deck_state.py status`，核对状态与实际文件，只继续未完成部分。新限制会让相关方案与生成任务失效（brief、字体方案、style_config、样页变化时 `deck_state.py` 自动把受影响的确认移入历史），无关阶段不重做。生成脚本的 run-state 独立保存输入 hash、输出及提交状态。

模板收藏状态由 `template-offer` 记录，规则见[模板库](template-library.md)。

## 降级

检索不可用：优先其他已可用的只读搜索工具或用户已给参考；都没有时可提出明确标为“拟议方向”的方案，不冒充检索结果。只有具体参考不可替代时才请用户补图。

生成不可用：保存完整方案和输入，锁定的 provider/model 不静默更换。尚未生成且用户允许时可改用内置工具；已生成部分页时先解释统一风格的影响，再按现有授权处理。

参考过多：待修页、必要品牌资产优先，其余按当前页面与故障需求选最少的有效参考。超过能力上限时明确说明如何调整，不随机丢引用。
