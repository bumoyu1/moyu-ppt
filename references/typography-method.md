# 字体系统与角色样张

中文字体影响 PPT 的语气与阅读效率。把“高级字体”拆成可执行的字形约束，再决定哪些角色需要视觉样张。整套先有同源字形、清楚层级，再作适合内容的变化。本文件是字体规则的唯一定义处；配置字段见 [style-config-schema.md](style-config-schema.md)。

## 默认根据内容设计与生成，不先搜字体

从当前材料的语气、实际标题字数、正文密度和已选整体风格，直接确定字形骨架、笔画与角色关系。需要有表现力的标题/重点字时，用实际文案生成T样张；正文、标签与数字采用统一清晰规范，在真实内容样页中生成并检查。不是每页另造一套字体，也不必给每种角色单独生图。

字体方案的依据可以是内容与设计推理，验证来自生成的字形样张和真实样页；不要求先找到外部中文字体图片。检索PPT案例时可以观察其文字层级，但不因此追加字体搜索，也不把外部字形当作生成前置条件。只有用户明确要求搜索、匹配具体外部字形且现有材料不足时，才按需检索；已有字体、品牌规范或T图优先直接用。用户泛称“字体参考图”默认理解为可生成的字形样张，不自动理解成上网搜图。

此规则不扩大任务范围：仅找灵感时给字体设计建议，plans仅交规范；实际生成仍按用户请求范围与已有授权执行。

## 先定义角色，再分配页型

| 角色 | 阅读任务 | 默认处理 |
|---|---|---|
| display | 封面、章节或极短观点的视觉焦点 | 可用展示字；每页通常一个主要短文本承担此角色 |
| title | 内容页标题，跨页建立稳定识别 | 固定字形体系，用尺度、换行和位置响应页面任务 |
| body | 连续解释和证据 | 常规清晰字形；优先可读、完整，不继承展示字装饰 |
| label | 图注、来源、流程节点等辅助文字 | 与正文同源，不能因次要而缩到难读 |
| data | 指标、表格、图表数值 | 明确数字形状、对齐方式、符号和单位 |

角色数量不等于字体数量。多数任务用一个稳定正文家族，加一个同源或有意对比的标题方向即可。display 可是 title 的更重或更有表现力的变体。整套角色先定好，各页选角色组合，不逐页随机换字体。已有品牌模板时，以既定规范为起点。

## 字形简报：从结构到效果

写足以区分方向的维度即可，不必每项堆形容词：

1. **骨架**：字面宽窄、部首关系、内部空间、横竖比例。先保证汉字结构完整。
2. **笔画**：粗细、粗细对比、转折、起收笔；说明细节作用位置，不要求所有笔画变形。
3. **重心**：视觉重心、基线、汉字与拉丁字母/数字的关系。
4. **间距**：字距、词间关系、行距；区分字形紧凑与整行挤压。
5. **表面**：边缘与材质，骨架稳定后才选择；正文和数值默认平涂、完整笔画。
6. **效果预算**：标题若有描边、浅浮雕或墨迹，只选能服务主题的少量效果，不能靠堆光晕、透视、破碎、贴纸遮挡制造设计感。

也写清对比：标题比正文更凝聚还是更舒展、数据更醒目还是保持同层级。“高端”“未来”可说明意图，不能替代结构描述。

## 何时制作 T 参考图

需要跨页统一标题时，把 T 字形图与 SZ 字号样板分开：紧裁大字图只传字形，完整画幅 SZ 只传墨迹高度和定位。还没有合格内容页时可用 `text_lock.py guide` 做原生几何辅助图，样页认可后用 `template` 提取真实样板；其字体不能被误当成指定字形。详见 [字号控制](title-size-control.md)。

**字体方案与实际效果必须展示，独立T图可以按需。** 在visual-proposal中用用户能理解的文字说明标题、正文、数字各选什么字形、搭配理由与预期效果。不要只写在JSON，也不要声称“标准字体无需样张”就结束字体设计。标准模式把字体纳入视觉方向选择；全篇生成前，真实样页必须让用户看到实际标题+正文（数据页还含数字）的效果。

适合：标题需要明确原创字形、用户重视封面级字体或已要求字形参考，或连续生成时标题漂移明显。这些情况优先准备title/display的T样张，不自行退回无说明的宋体/黑体。已有合格字形图可直接核对后使用。body/label/data通常不必分别生图，以实际内容样页验证清晰度即可。

可以省独立T图：只要方案且未授权生图，用户已确认品牌字体/合格模板字形，或设计判断普通字形足够且已向用户说明。用 `deck_state.py typography --specimen generate|provided|skip --reason … --summary …` 记录选择、理由与对用户展示的摘要。skip仍要在真实内容样页展示字体效果；plans任务则交清晰文字规范，不越界生图。需要原生可编辑/检索文字或精确字体文件排版时交presentations；当前图片PPT不自行叠文字层。参考图不是TTF/OTF，也不保证任意汉字无误迁移。

### 制作规则

- 一图一个角色，一个选定方向，只含给定的准确文字，不拼成有标题、标签、色板的“字体海报”。
- 默认黑字白底的中性平面样张，四周留出不裁字的空间。无场景、人物、道具、背景纹理、外部 Logo 或说明标签。
- 优先用当前页实际短文字；验证迁移时另用不同但有代表性的字，含可能出现的复杂部首、数字与标点。
- 字效与字形分开：默认 T 传骨架、笔画、重心和字内间距；最终颜色、投影、材质、字号、位置归页面简报。字内边缘质感也不能吞笔画。
- 保留原字符，不自动简转繁、繁转简、换同义字或修标点。输入有疑点就标出，不能借书法气质悄悄改字。
- 先视觉核对逐字、笔画与裁切，再登记 `typography.references`。未生成或未核对的路径不能当作通过的参考。

准备脚本不联网、不调用生图：

```bash
python3 scripts/typography_specimen.py \
  --config assets/examples/typography-style.json \
  --role title \
  --text '让复杂问题变清楚' \
  --output-dir assets/typography
```

可用 `--text-file assets/title-text.txt` 读取 UTF-8，保留字符；两者省略时，必须在该角色有 `sampleText`。输出 `title.prompt.txt`、`title.jobs.json`、`title.specimen.json`。jobs 供 `generate_slide_image.py --batch` 使用，计划图片是 `title.png`。打印 `planned_image` 不代表图片已生成；不要附全篇常量污染纯字样张。`--name title-v2` 保留多轮；同名同内容可重跑，内容变化用新名字或明确 `--overwrite`。

## 按页使用：独立的 T 角色边界

页面简报写：

```text
**[字体参考]**：[T-title] assets/typography/title.png — 仅标题
**[字体参考]**：[T-data] assets/typography/data.png — 仅关键指标数字
```

路径可由 `typography.references` 查找而省略。同角色多个候选须先选一个，不给互相冲突的样张。`referencePolicy.mode: off` 停用样张，保留文字规则；已有brief中要求遵循[T-role]的语句须改成独立字形文字规范，拆分预检会指出冲突，不静默删除文案或继续传图。

运行时生成图片编号与角色说明，禁止手填会过期的“第 2 张图”。T-title 只约束 title，不让 body/label/data 装饰化。T 不受 styleWeight/layoutWeight 控制。S 提供视觉气质、L 提供页面结构、T 提供指定字形、C 提供品牌或内容资产，不串用。

模型迁移约束必须包含：

> 只把该参考的字形特征用于本页指派角色。实际可见文字以本页逐字稿为准，不复制样张文字、角色标签、黑白配色、位置或背景。其余文字遵循各自角色规范。

冲突优先级固定：**字符与事实正确 → 可读性 → 层级与角色区分 → 字体效果 → 其他装饰**。出现错字或难辨结构，先减弱变形与效果；重试仍不稳定，改清晰标准字形。若图像路线仍无法满足准确性，明确该限制；用户选择原生文字方案后路由 presentations，不自行改变交付类型。

## 质量验证与证据边界

样张验收和跨页迁移分开：样张正确不代表迁移正确。检查不同标题文字能否保留字形、正文有无受干扰、是否复制样张内容、小数点/负号/%/单位是否正确、不同明暗背景下层级是否成立。对照样张与页面，也在最终投影或缩略尺寸看字。

自动化验证文本保存、角色隔离、任务格式与引用分工，不能证明图中文字正确或审美提高。OCR 只标疑点，仍需视觉核对。对照时保持内容、画布和模型条件一致，只改变是否用 T；分别记录标题一致性、正文可读、文字准确、额外内容、整体效果。没有实际生图或评审证据时，“字体参考提高效果”属于待验证假设。
