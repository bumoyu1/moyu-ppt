# Inspiration Search Method — 灵感检索与选择

目标：让用户从足够多、看得清的参考里自己挑。agent 负责写关键词、搜索、做成编号图库，并在用户挑完后整理成方向；哪些图好、哪种风格合适，由用户看图决定。

## 1. 先沟通整体感觉，再确定探索范围

先按[风格沟通](style-discovery.md)取得用户的整体感觉，或明确的开放探索授权；只给文章不能推定喜欢暗金、瑞士网格或任何其他风格。

先分开记录：

- **硬约束**：受众、用途、品牌色与字体、尺寸、交付媒介、用户明确指定的参考及跟随范围。
- **内容需要**：关键论点、需要解释的数据/流程/比较关系、必须支持的页型；隐喻是可选线索，不强制每套 PPT 场景化。
- **可探索变量**：用户尚未锁定的字体气质、布局密度、明暗、图像语言、色彩、材质、叙事表达。

精确指定模板、完整参考或已存配置足够支持任务时，可跳过搜索。宽泛风格何时可以直接搜、何时先追问一句，见[风格沟通](style-discovery.md)。若已有参考只覆盖封面，补的是内容页/数据页等缺口，已选风格保持不变。

## 2. 先看本地风格库

用户以前从图库里挑中并存下的参考图，在本地风格库里；整套交付后收藏的完整风格，在模板库里（[模板库](template-library.md)）。开始搜索前先查这两处，有合适的就省掉一次搜索：

```bash
python3 {SKILL_DIR}/scripts/ref_gallery.py library list --query "像素风"
python3 {SKILL_DIR}/scripts/template_library.py list --query "像素风"
python3 {SKILL_DIR}/scripts/ref_gallery.py library gallery --query "像素风" --out /tmp/moyu-ppt/refs/{deck}/library
```

- 有匹配：把库里的图做成编号图库，连同匹配的模板名称一起给用户看。用户挑中就不再搜索；说“去搜”或都不合适，再按下面的步骤搜。
- 没有匹配：直接搜，不必说明库是空的。
- 查库用用户说过的词和风格名，不用 agent 猜的风格标签。

## 3. 写关键词：AI 只负责这一步

搜回来的图由用户判断。agent 不按“合不合内容”“设计质量”替用户删图，也不先定好几个方向再去找配图：先定方向，搜索就只是在给 agent 的猜想找证据，用户想要的样子会被提前筛掉。

关键词分门类写，每个门类单独成组，图库里分开展示。版式管“怎么排”，风格元素管“画成什么样”，用户从两边各挑一两张，再搭配成方向（第 6 节）。

**用户点了名的风格**（一部作品、一款游戏、一个品牌、一位画师、一个流派名）：图库里只放和这个风格有关的东西，三个门类的每一条关键词都带这个风格的名字。

| 门类 | `purpose` | 搜什么 | 关键词怎么写 |
|---|---|---|---|
| 成套演示 | `system` | 这个风格现成的演示文稿 | 风格名 + 演示文稿的说法（presentation、slides、deck、keynote、PPT、スライド） |
| 风格里的版式 | `layout` | 用这个风格做的封面、目录、信息图、数据页等幻灯片页面 | 风格名 + 页型 + 演示文稿的说法 |
| 风格元素 | `image-language`、`material` | 这个风格自己的界面、图标与道具、场景与地图、纹理与边框、标志与纹样，以及它画的信息图。不必是幻灯片 | 风格名 + 元素词 |

- 把这个风格的叫法写进 `brief.style_terms`：用户的原词，加上最短最通用的叫法和其他要搜的语言里的叫法（如 `["pixel art", "像素风", "ドット絵"]`）。用户说过的更宽的说法（“某款游戏的像素风”里的“像素风”）也写进去，并各搜一组成套演示。脚本逐条检查，关键词里没有其中任何一个叫法就不通过。
- 成套演示或风格里的版式至少一组，风格元素至少一组，脚本会检查。现成的同风格演示稿往往很少，所以多搜这个风格画的信息图、界面和元素，把图库撑起来。
- 不带风格名的通用版式（流程图、对比页、定价表这类商务模板）不搜：它们和用户要的风格无关，放进图库只会添乱。内容页怎么排，从这个风格自己的演示稿、信息图和界面里借，或者按内容原创。
- 相近的风格或画法也不自己去搜（用户说的是某款像素游戏，就不拿 voxel、low poly 当它的风格元素）。
- 用户提出要看通用版式或相近风格时才搜：加一组，在这几条关键词上写 `"beyond_style": "用户的原话"`。

**用户没点名，只说了感觉，或让你先找**：`style_terms` 写 `[]`。版式组按这套内容用得到的页型写（页型或结构 + 演示文稿的说法）；风格元素组把用户的感觉拆成几种画法和视觉特征去搜，范围可以拉开，用户说过的词原样放进至少一组。

各门类都适用：

- 一共 6–8 组，每组 3–4 条。组名写在 `direction` 字段里，带上门类（如“成套演示·像素风”“风格元素·界面与图标”）；一组里不混版式和风格元素。
- 组内前两条最先搜，放这组最直接、彼此说法不同的两条；后面的是备用，用户要多看这一组时才搜（第 4 节）。
- 成套演示和版式的关键词都要带演示文稿的说法，否则搜回来的是海报和插画，脚本会拦。
- 中文、日文的说法放进对应门类的组里当其中一条；不同语言搜到的是不同的内容池。
- 同一个题材，每次都按这次用户的说法重新写，不照搬上一套作品的关键词。

关键词随图库一起给用户看；用户想加的词、想删的组，下一轮照改。

正式搜索写 `inspiration-plan.json` 并使用 `--require-brief`。`brief` 保留用户原话与探索范围；字体不搜，`brief.typography` 写生成计划。以下只示范格式：

```json
{
  "brief": {
    "style_intent": "复古游戏像素风",
    "style_terms": ["pixel art", "像素风", "ドット絵"],
    "audience_use": "培训课件",
    "content_needs": ["目录", "过渡页", "流程", "要点", "数据"],
    "typography": "选定方向后按需生成T样张，不另搜字体",
    "avoid": [],
    "exploration": "bounded",
    "scope": "directions",
    "decision": {"source": "user", "status": "confirmed", "evidence": "用户的实际原话"}
  },
  "queries": [
    {"query": "pixel art infographic presentation slide", "direction": "风格里的版式·信息图", "purpose": "layout",
     "basis": "用这个风格做的信息图页面，能直接参考排法", "target": "同风格的幻灯片页面"},
    {"query": "pixel art game interface icons", "direction": "风格元素·界面与图标", "purpose": "image-language",
     "basis": "用户点名像素风；风格元素带这个风格的名字", "target": "界面、图标与道具"},
    {"query": "pixel art presentation slides", "direction": "成套演示", "purpose": "system",
     "basis": "有现成的同风格演示稿就直接参考", "target": "成套演示文稿"}
  ]
}
```

`scope=supplement` 用于已定系统只补某类参考（如只缺数据页），此时 `brief.existing_style` 写明已定系统。`exploration=open` 需要用户明确表示没想法、先探索或由你决定；`style_terms` 必填，用户没点名风格时写 `[]`；`avoid` 未知可以为空，不编造。`decision` 引用实际对话，不复制示例原话。先离线预检：

```bash
python3 {SKILL_DIR}/scripts/pinterest_search.py --query-plan inspiration-plan.json --require-brief --validate-plan
```

## 4. 搜索并做成图库：搜多少，看多少

```bash
python3 {SKILL_DIR}/scripts/ref_gallery.py build --plan inspiration-plan.json \
  --out /tmp/moyu-ppt/refs/{deck}/gallery
```

- 搜索放在建图库这一步里，跟着要展示的量来搜。Pinterest 每次请求固定返回约 18 张，所以每组先搜前两条关键词（同时发出），这组的 6 张在两条之间轮流取：6 组就是 12 次请求，不再一次把所有关键词全搜一遍、搜回两百多张却只放三四十张。
- 某组前两条去掉重复后不够 6 张，或者请求失败，就接着搜这组的下一条；失败的关键词记在结果里，下次再试。
- 用户想一开始就搜得更宽，用 `--keywords 3`（每组先搜前三条）；只想让某一组多搜，用 `--more 组名 --keywords 3`，其他组不受影响。
- 每条关键词的返回都存在图库目录的 `search.json`；同一个图库里，搜过的关键词不再搜，`--rebuild` 也直接用存下的结果。
- 不按风格、好坏或合不合内容删图，按 Pinterest 的原排序放；同一张图在一个图库里只出现一次。以前给用户看过的图照样放：每套作品都是重新挑。
- 下载原图，图上印大号编号。拼图里每张图最宽 1280 像素，不放大：小图保持原大小，不会被拉糊。`large/` 里按编号放着每张图的原始尺寸（如 `large/07.jpg`），用户想看清某一张时直接给这一张。原图本身不到 700 像素宽的标“偏小”（那是上传者给的尺寸），不因此删掉。
- 产出 `index.html`（按门类分组、编号、点图看原图、来源链接；每组标出哪条关键词已搜、哪条是备用）、`boards/` 下每组一张编号拼图、`large/` 下每张图的原始尺寸、`gallery.json`（编号对应的候选）；给搭配建议时另有 `combos/` 下每套一张整版。在用户自己的浏览器里打开 `index.html`；只能在对话里看图，或预览窗口加载不了本地图片时，发 `boards/` 里的拼图，或起一个本地静态服务再打开。
- 用户想多看某一组：`ref_gallery.py build --out … --more 组名`，编号接着往下排。先放这组已经搜到、还没放的图，不够才搜这组的下一条关键词。用户想换个说法，就把新词加进这组，再 `--more`。用户提出要多搜、换词、加组，都照用户说的办。
- 请用户回复编号：版式里要用的一两张、风格元素里要用的一两张（成套演示里有合适的，可以一张两用），以及想存进风格库的其他几张。只给了编号、没说要存的，就只当这次用。
- 密钥解析：`--api-key` → `SCRAPECREATORS_API_KEY` → `configure.py set-key scrapecreators` 保存的本机文件 → macOS Keychain service `scrapecreators_pinterest_api_key`。没有 key 时按[首次配置](setup.md)引导用户到 https://app.scrapecreators.com/ 获取；日志和输出不回显密钥。没有自动检索时用用户给的参考，不能把内部设想冒充检索结果。
- 候选缓存放 `/tmp/moyu-ppt/refs/{YYYYMMDD-deck-name}/`，只有用户挑中的图进入作品目录或风格库。
- 已经有一份完整检索结果（`pinterest_search.py --output refs.json`）时，可以用 `build --refs refs.json --plan …` 直接做图库，不再发请求。

### 给搭配建议

图库做好后，先用拼图把全部的图翻一遍，挑出值得推荐的；再把这些图的原图逐张打开看（`large/NN`），然后给用户两到三套搭配建议。拼图是缩过的总览，只用来翻找，不凭它判断画风、材质和小字。图一张不删，建议只是帮用户少走几步：用户可以照一套选、混着选，或者不理建议自己挑。

每套建议写清四件事：

- 版式用哪几张（编号），借它的什么：页面骨架、面板形状、哪种页型是现成的。
- 画风和元素用哪几张（编号），借它的什么：配色、材质、图标或场景的画法。
- 这套内容里的页型各自怎么对应：流程页用什么表现、清单页用什么表现、封面和结尾怎么做。
- 短处：字多的页会不会吃力，哪种页型没有现成参考。

第一套放你最推荐的，说一句为什么。

每套建议拼成一张整版给用户看，一眼能看到这套搭起来是什么样：

```bash
python3 {SKILL_DIR}/scripts/ref_gallery.py combo --gallery /tmp/moyu-ppt/refs/{deck}/gallery \
  --set "游戏界面式=3,5,33,31" --set "明亮像素课件=12,7,40"
```

- 产出 `combos/01.jpg`、`combos/02.jpg`……每张的标题是这套的名字，左边是版式（封面参考、内页参考），右边是风格元素，每张图带着它在图库里的编号。整版用原图拼，不用拼图再拼。
- 用户说“按第一套”，用 `pick --suggestion 1` 记录；混着选或自己挑，用 `pick --use 编号`。

建议要从原图里来：没打开过原图的不推荐，图里看不清的东西不说。整版和拼图只给人看：写方向时描述的画风、附给生图模型的参考图，都用原图文件（`pick` 记下的那几张），不用拼图、整版或截图。借的是画法和排法；图里的官方标志、官方角色和别人的文案不进方向。用户回复后照常用 `pick` 记录；用户说“按第一套”，就把那一套的编号记为 `--use`。

## 5. 记录用户挑的图

```bash
python3 {SKILL_DIR}/scripts/ref_gallery.py pick --gallery /tmp/moyu-ppt/refs/{deck}/gallery \
  --use 3,17 --save 5,22 --tags "像素风,体素" --note "用户原话" --deck {deck}
```

`--use` 写出 `selected-refs.json`（含原图本地路径和每张图的门类）；只挑了一个门类时，结果里会有一句提醒，把它转告用户，由用户决定补不补。`--save` 把原图复制进风格库，记下来源链接、来自哪条关键词、标签和用户原话。没有用户的明确选择不写风格库。

## 6. 从用户挑的图整理成方向

用户挑完之后，agent 才开始归纳：

- 说清每张挑中的图分别提供什么——成套版式、某种内容页、画法与材质、配色、可融合的图像部件。这是描述，不是筛选；只有封面没有内容页、看不清正文之类的情况如实告诉用户，由用户决定换不换。
- 搭配：版式取自用户挑的版式图（页面骨架、分栏、层级），画风、配色、材质和图形元素取自用户挑的风格元素图。写清每张图只借什么：版式图不借它的颜色和画风，风格元素图不借它的构图。写进风格配置时，版式图是 `[L]`（`layoutRefImages`），风格元素图是 `[S]`（`styleRefImage`）。
- 只挑了一边时，问用户要不要补另一边；用户说不用，就写明那一边由你原创，等样页验证。
- 挑中的几张风格差得很远时，问一句以哪张为主，不自己取舍。
- 写 `visual-proposal.md`：用户挑中的图（稳定 ID）、整体感觉、内容页怎么排（没有现成内容页时写原创草案，标明待样页验证）、中文标题/正文/数字的字体建议（按[字体方法](typography-method.md)）。
- 写 `refs-review.md`：这轮的关键词分组、图库路径、用户原话、编号对应的 candidate_id 和每张的用途。
- 用户确认后按 [workflow-gates](workflow-gates.md) 记录 `deck_state.py decide visual --quote "用户原话"`。

## 7. 选定母本并锚定

图库已经下载了原图，`selected-refs.json` 里有本地路径；需要更清楚的版本时再用 `pinterest_search.py --download-original "{image_url}" --output …`。用原图做精读和 [S]/[L] 裁剪。拼贴图分摊像素属正常现象；关键结构确实看不清时，找同一参考的可读版本或说明缺口，不擅自替换用户挑中的图。生成模型的输出分辨率不能证明缺失的细节已经恢复。

选定后按 `style-config-schema.md` 和 `image-prompt-method.md` 保存来源与锚定角色：版式图担任 `[L]`；决定整体画风的一张可担任 `[S]`；人物、图标、图表画法写成全篇常量里的文字规范，不必每张都附图。

## 8. 风格库

- 位置：`${XDG_DATA_HOME:-~/.local/share}/moyu-ppt/references`（`--library` 可另指），和模板库并排，升级 skill 不会覆盖。
- 内容：用户从图库里挑中并说要存的参考原图，每张带来源链接、关键词、标签、用户原话和用过它的作品名。同一张图再次保存只合并标签和备注。
- 与模板库的区别：风格库存的是参考图，选方向时用；模板库存的是整套交付后提炼的完整风格（配色、字体角色、版式规则和参考图），复用整套风格时用。
- 下一套作品开始检索前先查风格库（第 2 节）。库里的图同样由用户挑，agent 不自动套用最近存的风格。

验证范围与证据等级见[检查与证据](quality-and-evaluation.md)。
