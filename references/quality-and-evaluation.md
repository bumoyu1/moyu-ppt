# 检查与证据

## 每套作品

1. 生成前：内容骨架通过检查（类型、主线、每节三项、原文依据逐字可查），文案稿经用户确认且方案里的可见文字与它逐行一致，方案逐页与骨架对位，覆盖表给用户看过；页序完整、常量存在、brief与清单非空、字形角色明确、源文件/静态参考可读；在提供密钥之前运行dry-run。
2. 所有图片：完整解码、尺寸比例、页数；以清单核对文字，关键数据/否定/单位逐项看图。每页有最少文字复核，复杂页额外检查布局与风格。比较页允许同骨架。
3. 字体：标题对应T角色，正文不染上标题效果；小字号不糊、笔画不粘、标点/数字/简繁正确。样张及迁移失败可降低字效或不用T，不删除文案。
4. 字号锁：声明了字号锁的作品，每批图先运行 `text_lock.py check`，看每组跨页的字高范围，连同总览图给用户看。重画哪几页由用户决定，测量不自动触发重画。
5. 品牌：对照原资产。二维码必须实际解码且匹配目标内容；不能用“看起来像”代替。
6. 全篇：总览比较层级、密度、风格与字体；每种新布局、数据页、资产页重点检查。再看三件事：封面、章节页、结尾是否各有各的构图，有没有被排成内容页的样子；是否有连续三页构图相同却没有阅读理由（应安排变奏）；是否有页的配色、材质或字形跳出了锁定项（变奏、亮点页重点看）。
7. PPTX：重开核对页数、次序、画幅，每页只有一张满铺图，无覆盖文字。

## 本地质量工具

同画幅样板和模板编辑的证据分两类：原页标题修正、不同标题/布局迁移。报告每页实际墨迹高与定位、组内波动、字符与正文保真；局部编辑没有逐像素保持承诺。单次或少量样本通过不能写成“字号已硬锁”或全篇可靠。既定容差保持不变，超差交用户决定，不能自动把目标改成输出值；操作见 [字号控制](title-size-control.md)。

`deck_delivery.py` 可先只检查，也可同时生成总览和PPTX。支持重复 --manifest 合并anchors/pages，并按page排序。任务里没写页号的按输出文件名 pXX 推断，重复/缺页阻断。

任务清单里带 `text_locks` 的页，`deck_delivery.py` 会用 `text_lock.py` 的同一套测量重新量锁定的每一行，结果写进报告的 `text_lock`：超差（`text_lock_drift`）算错误，不装配，除非该页 review-notes 有针对当前图片的 `text_lock_accepted`（`by` 与 `note` 都非空，对应用户的实际决定），此时降为警告 `text_lock_drift_accepted`；量不出来的行（`text_lock_unverified`）要求该页 checks 里有 `text_lock`。容差用 `--text-lock-tolerance-height`、`--text-lock-tolerance-position` 调整，放宽容差同样要有用户的决定。测量只说明墨迹框的高度与位置，不说明字写得对不对、好不好看。

默认 --ocr auto 在macOS使用本地Vision识别中文/英文和二维码，不联网；无Swift/Vision时明确unavailable。--ocr none用于已有人工/agent逐页检查的场合，不能声称OCR已做。OCR差异是疑点，识别无差异不证明画面无错误；图中文字顺序不同可能触发提示。

review-notes JSON按页号保存：`status=passed`、实际 `reviewer`、ISO格式 `reviewed_at`、当前图片的 `image_sha256`、字符串列表 `checks`。每页必需 `text`、`layout`、`style` 三项；有品牌引用时还需 `brand`，设置了 `qr_required` 或 `qr_payload` 时还需 `qr`。可另外记录 `typography`、`data` 等检查，不能用它们替代必需项。hash必须对应当前图片；旧图片的检查不自动用于重生成结果。

**二维码另需解码证据，单写 `checks: ["qr"]` 不算通过。** 任一二维码页必须满足以下一种情况：

- 本次本地工具状态为 `completed`，`qr_payloads` 为包含实际非空解码字符串的列表。
- 当前图片的有效 review-notes 中，另附 `qr_evidence`，同时记录实际解码方法 `method` 和实际解码内容 `payload`。例如用其他本地解码器或手机扫描，并记录扫描出的内容；不能仅凭外观填写目标链接。

如果 manifest 指定了 `qr_payload`，解码内容必须与它逐字一致；不自动归一化链接、标点或参数。仅设置 `qr_required` 而未给目标时，可验证“能解码”，报告的 `target_match` 为 null，不能声称已核对未提供的目标。不同解码证据与目标冲突时，保持失败，先查明错误再重新检查。

人工/其他解码器补证的记录示例（hash、检查者、时间及payload均应来自实际检查）：

```json
{
  "1": {
    "status": "passed",
    "reviewer": "实际检查者",
    "reviewed_at": "2026-09-09T10:00:00+08:00",
    "image_sha256": "从本次质量报告取得的当前图片SHA256",
    "checks": ["text", "layout", "style", "qr"],
    "qr_evidence": {
      "method": "手机相机实际扫码并读取内容",
      "payload": "https://example.com/actual-decoded-target"
    }
  }
}
```

没有有效审查记录，或二维码缺少实际解码证据时，`review_complete=false`。二维码未扫描/未识别时允许结构检查通过并生成待审PPTX，不能称作已经验证的正式交付；发现目标不匹配则阻断装配。`qr_verification` 单独记录解码状态与依据。OCR未运行时仍如实标记 `not_run`，不会因补了人工二维码证据就声称OCR已做。报告不能把“文件可打开”称为“字体视觉质量通过”。

## 技能评测

- tests/：本地确定性回归，网络用替身，验证候选去重/编号/补齐、引用角色、失败恢复、字符保真与PPTX完整性。
- 内容骨架：test_content_map 验证骨架格式、引文逐字核对（含换行与 PDF 提取留下的部首形字符）、逐页对位的各类错误、覆盖表，以及拆分和门禁的拦截。脚本查不了的是语义：主张提炼得对不对、标题与内容是否同源，仍靠人工核对和用户判断。
- 文案稿：test_page_copy 验证格式与出处标记、原文和引语的逐字核对、知识型引语默认不上屏、新增要写理由、与骨架对位、方案与文案稿逐行一致，以及确认后改动会被门禁拦住。脚本查不了措辞。
- 承接与递进：test_continuity 验证三项齐全、只有首尾页可写不适用、稳定页可同骨架、变奏与亮点页要有自己的构图方式。
- 图文预算：test_visual_budget 验证下限、低于基准要写原因、三分之二达到基准、封面/章节/结尾页的例外、写进 brief 的句子，以及没有声明预算的作品不受影响。比例写进提示词后的出图效果尚无对照。
- 字号锁：test_text_lock 用合成页面验证字框计算、字数预算、测量、偏差反馈与交付拦截。字框、字数统一和字号样板的出图效果只有小规模对照，属于 platform_image_smoke，不是稳定结论。
- evals/routing_cases.json：包含来源平台、否定、混合语言、阶段出口、单页近邻及原生可编辑边界。routing_tasks.json不带答案，可给独立agent做语义选择；这只叫agent_semantic_probe，不是实际app router运行。
- evaluate_routing.py只对外部提供的观察结果评分，不在评测器里用关键词制造预测。无观察结果不能报告通过。
- evals/inspiration_cases.json：冻结候选池，比较不用技能与使用技能两种输出的相关可用性、有效差异及约束内覆盖。图池/盲评未跑完时维持pending，不能靠候选数量充当审美分数。
- 字体：先角色样张，再迁移到不同文字的内容页；记录字形正确、正文隔离、样例内容泄漏、相邻页层级。一次小样只能证明本次表现，不证明所有字体或模型有效。
- 模板：test_template_library验证独立文件、引用改写、审批字段、版本和旧文案默认值隔离；template-routing-cases单独记录新增语义选择。template-workflow-cases记录完成后询问一次、拒绝/沉默、跨内容/品牌等交互验收计划，未跑真实应用对话时不能称已实机验证。
- 工作流：test_deck_state验证记录命令、确认内容变化后自动失效、样页必须有图、模板只问一次；test_workflow_gate验证缺确认、字体决策、样页图、页数画幅与native导出拦截。agent_behavior_probe模拟首回复，只证明该次模拟选择；实际公开交互记录与审美效果单独评价。

## 比较与证据等级

本节是证据等级的唯一定义处；其他文件提到“脚本不能证明审美/用户满意”时都按这里分级报告。

local_unit_test / mocked_runtime / static_lexical_smoke / agent_semantic_probe / platform_image_smoke / human_blind_review 分开记录。软件内部报告应包含runner、时间、输入/版本和结果。模型身份不公开就记platform-managed，费用未知记unavailable。不要把本地替身叫provider-backed。

视觉A/B保持同素材、同候选预算，随机化两版匿名展示，答案键与评价分开；reviewer、日期、理由及先评后揭晓记录齐全才计作人工结果。技能对比基线“不用skill”和版本对比“旧版”不是同一个实验。

评估不是新增固定禁令的理由。跨案例稳定有效的机制再进入核心规则，单次失败先变回归案例。已批准的用户偏好优先于默认策略。
